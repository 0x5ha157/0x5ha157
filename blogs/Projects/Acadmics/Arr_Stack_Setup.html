To run an efficient home server media pipeline, deploying inside an unprivileged **Linux Container (LCX)** on Proxmox VE offers near-native hardware speed with minimal RAM waste. Because Docker applications require isolation, the container configuration files must be modified to permit system nesting features prior to initializing package dependencies.

📃 PROXMOX LCX PRE-REQUISITES

1. Create a container using an **Ubuntu 22.04** or **Debian 12** template. Uncheck the "Unprivileged container" box if configuring direct NFS mounts, or keep it checked and enable **Nesting** under Options -> Features.

Method 1: Graphical Portainer UI Deployment

For users who prefer managing their environment via a web console, Portainer provides a high-fidelity GUI orchestration layer. Follow the terminal steps below to install Portainer, access its portal, and deploy your services.

STEP 1: PROVISION PORTAINER SERVER CONTAINER

Execute the following command block inside your root LCX terminal to map storage parameters and initialize the permanent management engine:

docker volume create portainer_data && \
docker run -d -p 8000:8000 -p 9443:9443 --name portainer --restart always \
-v /var/run/docker.sock:/var/run/docker.sock \
-v portainer_data:/data portainer/portainer-ce:latest

Open your web browser and navigate to https://[LCX_IP_ADDRESS]:9443 to create your administrative profile.

STEP 2: GUI STACK DEPLOYMENT STEPS

  1. [1] Log in to Portainer and select your Local Environment.
  2. [2] Navigate to the left sidebar menu and click Stacks -> Add Stack.
  3. [3] Name the template arr-production-stack.
  4. [4] Copy and paste the configuration schema from the Docker Compose tab into the web editor window, then click Deploy Stack.

Method 2: Command-Line Infrastructure as Code (YAML Stack)

Deploying your configuration via terminal automation offers full environment control. This single script sets up your persistent storage directory boundaries, maps internal ports, and handles container dependencies.

📦 UNIFIED PRODUCTION DOCKER-COMPOSE.YML FILE

TARGET PATH: /opt/arr-stack/docker-compose.yml 
version: "3.8"
services:
  prowlarr:
    image: lscr.io/linuxserver/prowlarr:latest
    container_name: prowlarr
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
    volumes:
      - /opt/arr-stack/prowlarr-config:/config
    ports:
      - 9696:9696
    restart: unless-stopped

  radarr:
    image: lscr.io/linuxserver/radarr:latest
    container_name: radarr
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
    volumes:
      - /opt/arr-stack/radarr-config:/config
      - /data:/data
    ports:
      - 7878:7878
    restart: unless-stopped

  sonarr:
    image: lscr.io/linuxserver/sonarr:latest
    container_name: sonarr
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
    volumes:
      - /opt/arr-stack/sonarr-config:/config
      - /data:/data
    ports:
      - 8989:8989
    restart: unless-stopped

  qbittorrent:
    image: lscr.io/linuxserver/qbittorrent:latest
    container_name: qbittorrent
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Etc/UTC
      - WEBUI_PORT=8080
    volumes:
      - /opt/arr-stack/qbittorrent-config:/config
      - /data:/data
    ports:
      - 8080:8080
      - 6881:6881
      - 6881:6881/udp
    restart: unless-stopped
To activate this stack, run mkdir -p /opt/arr-stack /data && cd /opt/arr-stack, paste the text block above into a new docker-compose.yml file, and execute: docker compose up -d

CRITICAL SERVICE POST-INSTALL CHECKS

CHECK_01 Atomic Hardlink Moves
Verify that torrent data folder allocations share a matching root folder mount point with Radarr/Sonarr to prevent disk I/O performance bottlenecks.
CHECK_02 Prowlarr Integration Sync
Navigate to Settings -> Applications inside Prowlarr to push tracker definitions and API endpoints to your indexers simultaneously.
CHECK_03 UID/GID Permissions Alignment
Ensure the user variables (PUID=1000) defined within your Docker configuration match the owners of your host system's data folders.
CHECK_04 Proxmox Backup Stratums
Schedule daily, automated Proxmox snapshots targeting your container configuration folder volumes (/opt/arr-stack) to ensure swift disaster recovery.
