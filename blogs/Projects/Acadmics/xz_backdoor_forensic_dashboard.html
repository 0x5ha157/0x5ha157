Mathematical \& Structural Attack Path

This section breaks down the logical dynamic linkage hook vector utilized during CVE-2024-3094. The malware targets the compilation routine of sshd, specifically intercepting runtime bindings during GNU C Library (glibc) dynamic resolver execution.

IFUNC RESOLUTION MECHANICS

Glibc uses Indirect Functions (IFUNC) to optimize mathematical execution paths at loading time. Under normal conditions, sshd resolves dependencies cleanly:

sshd --> libsystemd --> liblzma (Standard CRC64)

During target compromise, however, the malicious dynamic loader hooks crc64_resolve. Before returning, it dynamically patches the Global Offset Table (GOT) mapping for decryption:

GOT[RSA_public_decrypt] = Hook_Redirect_Function

DYNAMIC BINDING INTERCEPTION FLOW

  1. [1] Systemd starts, initializing the sshd service dependencies.
  2. [2] Malicious code within liblzma.so is processed prior to public RSA setup.
  3. [3] Backdoor patches GOT, intercepting all SSH pre-authentication keys.
  4. [4] If signature validates, shellcode spawns root subshell without logs.
